원칙: 이번에 돌려서 본 증거 없이 완료를 말하지 않는다(CLAUDE.md "확인하고 말한다").

## 말하기 전에

1. 무엇이 그 말을 증명하는지 정한다(명령, 화면 캡처, DB 조회).
2. 지금 그 명령을 끝까지 돌린다. 예전 결과나 일부만 돌린 결과로는 말하지 않는다.
3. 출력을 끝까지 읽는다: 종료 코드, 실패·건너뜀 개수.
4. 결과가 말과 맞을 때만, 숫자와 함께 말한다. 안 맞으면 실제 상태를 그대로 말한다.

| 말 | 필요한 증거 | 부족한 것 |
|---|---|---|
| 테스트 통과 | 이번 실행의 통과·실패·건너뜀 개수(실패 0) | 이전 실행, "통과할 것" |
| 린트·타입·서식 통과 | 그 명령의 출력(오류 0) | 다른 검사 통과 |
| 빌드 됨 | `cd rust && ./build.sh --release`와 `docker build --target ripple .`(이미지 하나) 둘 다 종료 코드 0 | 린트·타입 통과 |
| 버그 고침 | 원래 증상을 다시 해 봐도 안 나옴, 그 증상의 테스트 통과 | 코드를 바꿨음 |
| 회귀 테스트 됨 | 고침을 되돌리면 실패, 다시 넣으면 통과 | 한 번 통과 |
| 화면 됨 | 캡처를 직접 열어 봄(데스크톱·모바일) | E2E 통과 |
| fork·subagent가 한 일 | `git diff`와 출력으로 다시 확인 | 보고에 "성공" |
| 단계 완료 | SPEC 10장 완료 기준을 하나씩 대조 | 테스트 통과 |
| 배포 됨 | `/deploy` 4장 확인 항목 결과 | 컨테이너가 떠 있음 |
| 비용 | 사용량 기록(`usage_logs`) 합계 | 예상 비용 |

## 멈출 신호

- "아마", "될 것", "~인 것 같다"를 쓰려 할 때
- 확인하기 전에 "완료", "됐습니다"를 쓰려 할 때
- 일부만 확인하고 넘어가려 할 때, 다른 검사가 통과했으니 이것도 되겠다고 여길 때

확인하지 못한 것은 확인하지 못했다고, 이유와 함께 적는다.
