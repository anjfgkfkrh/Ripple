## 브리프에 없던 결정
- 예/아니오 질문 `type`을 브리프의 `"boolean"` 대신 `"noul"`로 보냈다 — 첫 호출이 `"boolean"`으로 HTTP 400이어서 SDK 0.7.0 `index.d.mts`(NoulQuestion)를 읽어 고쳤다(SPEC 291줄은 "boolean"이라 부르지만 API 이름은 noul). 400은 비용 0으로 본다.
- 범위 밖: `.gitignore`(저장소 루트)는 건드리지 않고 `work/article-classify/measure/.gitignore`에 `data/`를 둠 — 범위 안이고 요청·응답이 제목을 담아서.
- 표본 형식 기사 10건 선택 규칙(스크립트 `PAT`): 포토·자막뉴스 `[포토]`·`[사진]`·`[자막뉴스]`는 화면 기준을 넘는 이름 연결 기사가 4건뿐이라 전부 쓰이지 않고 **`[자막뉴스]` 4건**(`[포토]`·`[사진]` 없음)이 뽑혔다. 뉴스 모음은 `[...브리핑]`·`이슈 종합`·`이슈픽`·`모닝`·`조간`·`外`로 끝남 같은 머리말 규칙으로 골랐고 실제 모음이 아닌 것이 섞인다(s45·s46 제목은 단일 주제). 기자수첩 1건은 화면 기준 미달(관련도 9.9, 영향도 4.7)이라 채웠다(`tag`에 표시). 사설·기자수첩·칼럼은 한 건씩.
- 표본 ①·④는 종목 이름 연결 중 화면 기준을 넘는 것만 뽑았다. 지난 평가 규칙(c)은 이름 연결로 한정하지 않았다(브리프 글자대로 종목 항목 전체).
- (c) 같은 기사의 시장 평가 관련도는 시장 항목 평가 중 최댓값, 화면 기준을 넘는지는 보지 않았다. (a) 같은 소식은 화면 기준을 넘는 기사끼리만, 항목 구분 없이 24시간 안 앞선 기사로 셌다(`similar_title.rs` 규칙 이식, 제목 완전 일치 대체는 쓰지 않음).
- (d) 영문 별칭 `kospi`·`kosdaq`은 소문자로 맞춘 뒤 찾아 0건이었다(한글 `코스피`·`코스닥`만 걸림). 연결 있음 판정은 `article_matches`에 그 시장(KR/US)의 `kind='market'` 항목이 있는지로(match_kind 무관).
- 일관성 정의: "같은 쪽" = 3번 모두 0.5 이상이거나 모두 미만. 확률 평균·최소·최대는 묶음 안 기사×3번 값 전체, "흔들림"은 기사별(최대−최소) 평균. 종목 점수는 응답 `score`를 2배로 저장값(0~10)과 맞춤(keyword-topic `jev_read.py`와 같음).

## 발견한 것
- 같은 요청 3번의 확률이 거의 같다: 성격 질문 흔들림(기사별 최대−최소) 평균이 모든 묶음에서 0.00~0.02, 종목 점수 관련도 흔들림 0.03~0.08(0~10 척도). 3번 조합이 갈린 기사는 50건 중 3건(전부 ④).
- 종목 요청의 `relevance`·`magnitude`는 저장값(원래 평가 요청과 질문 묶음이 달라 새로 묻는 값)과 대체로 같으나 회사 묶음 크기(영향도)가 평균 −0.58 낮다(위 표).
- API 이름은 `noul`이다(`boolean` 아님). 구현 단계의 해석 코드는 `answers.<이름>.noul`을 읽어야 한다.
- 시장 항목은 DB에 KR "한국 증시"·US "미국 증시" 둘 다 있다(`stocks.kind='market'`).
