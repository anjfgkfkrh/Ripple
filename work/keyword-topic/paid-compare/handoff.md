## 추론 설정 값 (OpenRouter 문서)
- 문서: https://openrouter.ai/docs/use-cases/reasoning-tokens (WebFetch 요약으로 확인, 원문 직접 낭독 아님)
- 끄기: `reasoning: {"enabled": false}`(통합 형태), `reasoning.effort: "none"`("Disables reasoning entirely"). 줄이기: `reasoning.max_tokens`(Anthropic은 그대로 예산으로 씀, 최소 1024), `reasoning.effort`(Anthropic은 예산으로 변환). "`max_output_tokens` must be strictly higher than the reasoning budget". `exclude: true`는 응답에서만 숨기고 토큰은 청구됨.
- 구조화 출력·`require_parameters`와의 관계는 문서에 없음. **실제 응답으로 확인**: `provider.require_parameters: true` + json_schema strict + 아래 값 모두 HTTP 200, 형식 통과.
  - `{"enabled": false}`: 200 (끔 요청 전체 사용)
  - `{"effort": "none"}`: 200, 추론 0
  - `{"effort": "low"}`: 200, 추론 0
  - `{"max_tokens": 1024}`: 200, **추론 1,493토큰이 붙음**(끄는 값이 아니라 예산을 주는 값; 이 요청은 출력 2,511)

## 브리프에 없던 결정
- 창 3개 중 (a) 토픽 창은 창0·창1로 정함(브리프는 "창 2개"만 지정). 창 시각은 지난 실측과 같은 순서(백업 시각, 마지막 갱신, 그 전 갱신).
- "안 보임" 창0·1은 (a)의 끔 요청 재사용(비용 절약), 창2는 따로 보냄. 지금 입력은 결과를 안정적으로 보려고 2번째를 추가로 보냄(+약 $0.011), 탐침 3번 추가(+약 $0.003).
- `scripts/`의 `llm_make.py`에 `pc` 단계를 더함(저장소 원본은 안 고침). `pc_read.py`는 임시 폴더 경로(`.paid-w`)를 읽도록 쓴 것이라 지금은 `data/`를 가리키게 바꿔야 다시 돌 수 있음.
- 요청·응답 원문과 창별 이전 토픽 JSON을 `data/`에 보관(작업 폴더 안; DB 사본은 지움). 응답에는 뉴스 제목 일부와 모델 생성물이 들어 있고 키는 없음.
- 범위 밖 변경 없음(`git status`: `work/metrics.csv`만 이전부터 있던 파일).

## 발견한 것 (함정, 실패 교훈, 기존 코드의 버그)
- `reasoning.max_tokens`는 "줄이기"가 아니라 추론을 켜는 값이었다(예산 1024에 1,493토큰이 붙음). 끄려면 `enabled:false` 또는 `effort:"none"`.
- 이번 28번 중 끈 값 없이 보낸 21번은 추론 0 — 추론 유무는 모델·시점에 따라 갈릴 수 있다.
- 창2에서 id를 하나도 못 쓴 원인 미확인.
